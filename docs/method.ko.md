# 도서관 운영 방법

도커 설치에서 각 실의 작업 기록은 프로젝트의 데이터베이스와 실 서비스의 메모리에 남습니다. 검색할 때 사용자 질문 원문을 `--question`으로, 에이전트가 고른 검색어를 별도로 전달합니다. 사서는 다시 쓸 만한 답을 골라 `benedict file --id 기록번호`로 원문·답·출처를 위키 서류철에 남깁니다. 서가 원본은 선택한 저장 위치에 그대로 둡니다.

## 에이전트가 도서관에서 일하는 법

도서관은 원문을 확인해 정확하게 판단하고, 그 판단의 이유를 다른 에이전트가 이어 쓸 수 있게 하는 작업 공간입니다. 여기서 에이전트는 자료를 읽고 판단하고 행동하는 주체이고, 페르소나는 사람이 디지털 공간에서 자신을 표현하는 정체성입니다.

새 일을 받으면 먼저 해당 프로젝트에서 이미 내린 결정과 그 이유를 찾습니다. 어디에 기록됐는지 모르면 중앙도서관에서 접근이 허용된 도서관을 찾습니다. 혼자 일할 때는 열람실에 원문과 작업 중인 질문을 함께 두고, 지난 결정의 근거가 이번 일에도 적용되는지 확인합니다. 여전히 유효하면 그대로 이어가고, 조건이 달라졌으면 무엇이 달라졌는지 밝힙니다. 주인이 결정해야 할 쟁점이 남을 때 그 쟁점을 묻습니다.

내부 근거가 부족하거나 오래됐으면 에이전트가 자기 웹 검색 도구로 공개 자료를 찾습니다. 찾은 원문은 도서관의 `web-source` 명령으로 보관하고, 저장된 원문을 읽어 확인한 답을 남깁니다. 도서관의 공용 검색 계정은 필요하지 않습니다.

일을 시작할 때는 지난 결정과 함께 **그 일을 수행하는 스킬**도 찾습니다. 스킬 문서는 작업 절차와 관련 자료를 연결하는 위키 문서입니다. 그 절차의 근거가 된 연구·원자료는 서가에 둡니다. 사서는 확정된 스킬 원문과 판을 위키의 서지 레코드에 연결합니다. 에이전트는 검색실에서 그 카드를 찾고, 열람실에서 해당 판의 원문과 필요한 딸린 파일을 읽어 이번 일에 적용합니다. 실행 결과와 근거는 해당 도서관의 서류철에 남깁니다.

함께 일할 때는 회의실 과제에 원문과 해결할 질문을 한 번 올립니다. 동료는 과제 이름으로 같은 자료를 열고 판단을 보탭니다. 일이 끝나면 맡은 에이전트가 결론과 이유, 근거가 있는 원문, 남은 질문을 해당 도서관 서류철에 남깁니다.

예를 들어 다음 에이전트가 현장 조사 물품을 주문한다고 합시다. 프로젝트 기록에서 “기존 주황색 표식과 구별하려고 보라색을 쓴다”는 결정을 찾아 읽었다면, 같은 현장의 주문서에 보라색을 반영할 수 있습니다. 새 현장에서 이미 보라색을 쓴다면 색을 다시 정해야 하는 이유도 설명할 수 있습니다. 다음 에이전트의 실제 작업에 그 이유가 쓰였는지가 인계의 기준입니다.

## 운영 방법

1. **도서관마다 정보 경계를 둡니다.** 컨테이너·계정 하나가 위키와 실을 맡습니다. 서가 원본은 읽기 전용,
   위키·색인·실 스냅샷은 전용 쓰기 볼륨에 둡니다. 등록부는 대상을 고르며 OS 권한을 새로 주지 않습니다.
2. **찾은 뒤 판단합니다.** 선택한 검색실·색인에 묻습니다. 검색 실패·접근 실패·실제 결과 없음을 구분합니다.
   낱말 검색은 지원하는 설정이며 벡터 검색이라고 부르지 않습니다.
3. **원문을 열람실로 가져옵니다.** 검색이 가리킨 문서를 읽고 경로·판을 남깁니다. 협업할 때는 이름 있는
   열람실 변수에 보존합니다. 검색 발췌는 근거로 가는 안내이며 원문 대조를 대신하지 않습니다.
4. **회의실로 일을 나눕니다.** 과제·회신함에 질문·입력·상태·답을 둡니다. 다음 작업자가 비공개 대화 기억에
   의존하지 않고 이어받을 수 있게 합니다.
5. **답한 질문을 서류철에 남깁니다.** 질문·답·근거를 마크다운에 기록합니다. 저장 거부 사유를
   숨기지 않습니다. 원문으로 검증한 답이 쌓여야 하며 요약끼리 서로 인용해 근거를 대신하지 않습니다.
6. **사서가 층을 맞춥니다.** 외부 편집 뒤 색인·실 원문을 갱신하고 실제 시작·끝·결과를 일지에 씁니다.
   동기화·평가 실패를 최신 파일 시각이나 성공으로 바꾸지 않습니다.
7. **답을 아는 질문으로 잽니다.** 골든셋은 정답 원문을 지정하고 순위·적중·시간을 보고합니다. 답의 낱말
   포함률은 의미상 정답과 다릅니다. 배포 예제는 합성 자료만 사용합니다.
8. **커밋한 스킬을 입고합니다.** 명시한 도서관에 불변 Git 원문·커밋·파일/트리 해시를 담습니다. 초안이
   공용판을 덮지 않으며 수기 문서와 더 최신 판을 보존합니다.
9. **기록의 연속성을 복원으로 확인합니다.** 위키를 Git 스냅샷과 검증 가능한 백업으로 남기고 새 위치에
   복원해 대조합니다. 실 상태·DB 백업은 별도 책임입니다.

실행 예제는 [에이전트 사용법](agent-usage.md), 남은 운영 전환은 [범위 감사](scope-audit.md)를 따릅니다.
원문이 바뀌면 새 근거로 파생 기록을 갱신하고 이전 판은 이력에 보존하여 옛 기록이 현행처럼 남지 않게 합니다.
